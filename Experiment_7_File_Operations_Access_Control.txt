EXPERIMENT 7 - FILE OPERATIONS AND ACCESS CONTROL IN LINUX
===========================================================

Aim:
Implement file operations and access control in Linux.

IMPORTANT:
This guide assumes you may get a completely fresh Kali Linux PC in the lab.
Do ALL steps from the beginning. Do not assume anything from another experiment
has already been configured.


PART A - FILE OPERATIONS USING C
================================

1. Open terminal and create the C program:

nano exp7.c

2. Paste this program:

#include <stdio.h>
#include <stdlib.h>

int main()
{
    FILE *fp;
    char data[100];

    // Create and write to a file
    fp = fopen("sample.txt", "w");
    if (fp == NULL)
    {
        printf("Error opening file\n");
        return 1;
    }

    fprintf(fp, "Hello Linux File Operations");
    fclose(fp);

    // Read from the file
    fp = fopen("sample.txt", "r");
    if (fp == NULL)
    {
        printf("Error opening file\n");
        return 1;
    }

    fgets(data, sizeof(data), fp);
    printf("Data read: %s\n", data);

    // Find file size
    fseek(fp, 0, SEEK_END);
    long size = ftell(fp);
    printf("File size: %ld bytes\n", size);
    fclose(fp);

    // Rename file
    if (rename("sample.txt", "renamed.txt") == 0)
        printf("File renamed to renamed.txt\n");
    else
        printf("Unable to rename file\n");

    return 0;
}

Save in nano:
CTRL + O
ENTER
CTRL + X


3. Compile:

gcc exp7.c -o exp7

If gcc is not installed:

sudo apt update
sudo apt install gcc


4. Run:

./exp7

Expected output:

Data read: Hello Linux File Operations
File size: 27 bytes
File renamed to renamed.txt


PART B - VERIFY FILE OPERATIONS
===============================

5. Check that the renamed file exists:

ls -l renamed.txt

Typical output:

-rw-r--r-- 1 kali kali 27 ... renamed.txt


6. Display its contents:

cat renamed.txt

Expected:

Hello Linux File Operations


PART C - ACCESS CONTROL / FILE PERMISSIONS
==========================================

Linux permission values:

4 = Read (r)
2 = Write (w)
1 = Execute (x)

The permissions are arranged as:

OWNER | GROUP | OTHERS

Example:

rwx rwx rwx
--- --- ---
 ^   ^   ^
 |   |   |
Owner Group Others


Useful maths:

4 = read
2 = write
1 = execute

4 + 2 = 6 = read + write
4 + 1 = 5 = read + execute
2 + 1 = 3 = write + execute
4 + 2 + 1 = 7 = read + write + execute


Examples:

444 = r-- r-- r--
      read-only for owner, group and others

644 = rw- r-- r--
      owner can read/write; group and others can read

755 = rwx r-x r-x
      owner has all permissions; group and others can read/execute


PART D - MAKE FILE READ-ONLY
============================

7. Change renamed.txt to read-only:

chmod 444 renamed.txt


8. Verify:

ls -l renamed.txt

Expected permission section:

-r--r--r--


9. Try writing to it:

echo "New Data" >> renamed.txt

Expected:

zsh: permission denied: renamed.txt

This demonstrates ACCESS CONTROL:
The file exists, but the current user cannot write because write permission
has been removed.


PART E - RESTORE WRITE PERMISSION
=================================

10. Give the owner read + write permission and everyone else read permission:

chmod 644 renamed.txt


11. Verify:

ls -l renamed.txt

Expected permission section:

-rw-r--r--


12. Try writing again:

echo "New Data" >> renamed.txt

There should now be NO permission error.


13. Check the contents:

cat renamed.txt

Expected:

Hello Linux File OperationsNew Data

NOTE:
"New Data" may appear directly after "Operations" because the original C
program did not place a newline at the end of the text. This is completely OK.

WHAT EACH IMPORTANT COMMAND DOES
================================

nano exp7.c
Creates/opens the C source file.

gcc exp7.c -o exp7
Compiles exp7.c and creates executable "exp7".

./exp7
Runs the compiled program.

ls -l renamed.txt
Shows file information including permissions, owner and group.

cat renamed.txt
Displays file contents.

chmod 444 renamed.txt
Sets read-only permission for owner, group and others.

chmod 644 renamed.txt
Gives read/write to owner and read-only to group and others.

echo "New Data" >> renamed.txt
Appends text to the file. This fails under 444 and succeeds under 644.


HOW TO READ THIS:
=================

-rw-r--r--

Ignore the first "-" for now (it indicates an ordinary file).

Break the remaining 9 characters into three groups:

rw- | r-- | r--
 ^     ^     ^
 |     |     |
Owner Group Others

Owner = rw- = 4 + 2 = 6
Group = r-- = 4
Others = r-- = 4

Therefore:

rw-r--r-- = 644


FINAL RESULT
============

File operations such as file creation, writing, reading, finding file size
and renaming were demonstrated using a C program.

Linux access control was demonstrated using chmod by changing file permissions
between 444 (read-only) and 644 (owner read/write, others read-only).
